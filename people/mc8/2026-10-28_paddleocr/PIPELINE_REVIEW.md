## Preserved evaluation semantics

- Reference labels are not loaded by the inference worker or runner. The PDF and model weights supply predictions. No inference calls a hosted API or LLM judge.
- Native PDF text is used only for metadata and Sam's explicitly labeled text-layer diagnostics. It does not supply PaddleOCR predictions.
- Markdown tables are converted by Sam's unchanged canonical adapter; native HTML spans and all numeric errors remain. Image paths are made unique per physical page to prevent crop collisions. Images are never treated as recognized numeric evidence.
- The common confidence field stays `null`. Native OCR scores remain in raw JSON; they are not calibrated document confidence.
- Default scoring uses only human-reviewed/adjudicated references, currently zero. Draft scores are explicitly preliminary. Missing pages/cells and ambiguous matches retain Sam's failure semantics and denominators.
- Existing baselines are frozen predictions, not reruns. Runtime comparisons span different dates/hardware. Paddle timings include native output persistence, while canonical export and scoring are outside the timed subprocess.
- All 24 historical per-document metric dictionaries, pooled scores and integer counts reproduce exactly. One MinerU VLM equal-document metadata mean differs by `2.22e-16` between Python 3.10 and Sam's Python 3.12. [Python changed float summation in 3.12](https://docs.python.org/3/library/functions.html#sum). Baseline verification permits `1e-14` roundoff only for `equal_document_mean`; it does not alter the scorer, returned values or other comparisons.
- These are Sam's custom diagnostics, not official OmniDocBench, TEDS, FinCriticalED or TAT-QA leaderboard scores. TAT-QA belongs to the earlier mc8 experiment and is not part of Sam's executed pipeline.

## Necessary engine-specific settings

PP-StructureV3 runs locally with four Paddle CPU math threads, default pretrained layout/table models and the official `PP-OCRv5_mobile_det` / `PP-OCRv5_mobile_rec` OCR models. OpenMP/BLAS environment thread counts stay at one, as requested by the native wheel. A four-thread diagnostic on identical EDF page pixels produced identical Markdown and reduced runtime; `results/cpu_configuration.json` records it. The server recognizer proved impractically slow on this Intel CPU during preflight, before accuracy scoring; the mobile models support both the English PDFs and Chinese OmniDocBench pages. This is a declared CPU configuration of PP-StructureV3, not a result for its server-OCR preset. Table recognition is enabled. Formula, seal, chart-description, page unwarping and orientation subpipelines are disabled; no generative figure interpretation is added. Every sponsor page receives image parsing, matching the all-page OCR comparator rather than PyMuPDF's automatic OCR routing. These settings and exact package/model hashes are recorded per run.

The pinned PaddleX 3.3.13 implementation initializes its 1.4 GB Chart2Table model even when chart recognition is disabled. `paddle_worker.create_pipeline` narrowly skips that unused initializer and restores the factory immediately after construction. All actual layout, OCR and table predictors use PaddleX's original model factory and pretrained weights. No recognition outputs are substituted. Paddle's default Markdown filter also drops notes and page furniture; prediction calls explicitly set `markdown_ignore_labels=[]` to retain those classes, as Sam's exporter does.

The Intel macOS PaddlePaddle 3.0.0 wheel crashed inside `phi::funcs::im2col_common<float>` on the full-size OCR detector tensor. The detector therefore uses `text_det_limit_side_len=1280, text_det_limit_type='max'`, consistent with the upstream [large-image macOS issue and temporary size boundary](https://github.com/PaddlePaddle/PaddleOCR/issues/16457). PDF rendering and recognition crops remain at 300 DPI; this bounds the detector's internal input, and may affect small-text detection. The same setting is fixed across every document and benchmark sample. No accuracy labels were inspected to choose it.

Official API reference: [PaddleOCR PP-StructureV3](https://www.paddleocr.ai/v3.3.0/en/version3.x/pipeline_usage/PP-StructureV3.html). PaddleOCR 3.3.3 and PaddlePaddle 3.0.0 are selected for native Intel macOS CPU wheels; `requirements-lock.txt` records the environment actually used.
