# Methods, reproducibility and adaptations

## Source and scope

Sam source: commit `9e53e322821b5d9aea6bdcc170c0adfa56bcf039`, especially `people/samhu/2026-11-15_table_confidence/prototype/`. `sam-code-lock.json` pins the scientific functions used here. Recognition weights stay fixed. Original results, references, human reviews and calibrators are never overwritten or reused as new CPU calibration.

This experiment evaluates already-cropped FinTabNet table images. It does not measure full-PDF layout recall. PP-DocLayout_plus-L is downloaded as an optional future PDF-preparation component; it is not a seventh recognizer and is not run on these crops. The six sponsor PDFs and 17 extra-report crops are not included in the 2,000-table FinTabNet count.

## Hardware and runtime

Intel Core i5, four cores, 2 GHz, 16 GB RAM; Intel Iris Plus. CPU runtime uses four threads, Apple Accelerate, 8,192 context tokens, 256-token prefill batches, and at most 4,096 generated tokens. OMP is limited to one thread to avoid Paddle/OpenBLAS oversubscription. Images for the VLM adapter have maximum side 1,536, preserving aspect ratio; original input bytes/hashes are retained. Model-specific image encoding then runs in llama.cpp. Peak runtime memory has not been measured. Saved per-output recognition timings for the completed 300-table prefix are reported in [the published snapshot](results/300_tables/summary.md); they exclude separate scoring and calibration time.

`runtime-build.json` records the compiled executable, adapter source and pinned llama.cpp revision `52975342ff6b85127ff31930d39e36725fd08809`. The local Xcode launcher fails, so the build uses the installed CommandLineTools compiler/SDK directly, with the SDK's complete libc++ headers. Metal/CUDA and vision warmup are disabled. Compiling the binary and invoking `--help` do not load recognizer weights.

CPU Python uses PaddleOCR 3.3.2 / PaddleX 3.3.13 with **PaddlePaddle 3.0.0**, the available Intel wheel, instead of Sam's 3.2.2. Tesseract 5.5.3 and its English data match Sam. PP-OCRv5 mobile detector/recognizer weights match his recorded hashes. Full versions are in `requirements-cpu.lock.txt`. `.venv` currently links to the existing project CPU environment; reproducible setup can create an independent local environment.

## VLM conversion

Exact repositories and source revisions appear in `config.json`. MinerU is the **MinerU2.5-Pro-2605-1.2B recognition component**, not a different MinerU pipeline checkpoint. MonkeyOCR uses only its `Recognition/` component. Their configs declare Qwen2-VL and Qwen2.5-VL architectures respectively. PaddleOCR-VL and GLM-OCR use their own supported architectures.

`download_assets.py` resolves immutable revisions and checks LFS SHA-256 values, with resumable bounded HTTP ranges. `prepare_models.py` converts language tensors and image-encoder/projector tensors separately to F16 GGUF. The isolated conversion environment uses Torch 2.2.2 and Transformers 4.57.6; it never instantiates a recognizer or generates output. Missing Qwen configuration defaults are filled from the pinned official configuration classes. Configuration changes and source/converted hashes are recorded in `model-conversions.json`; original HF snapshots remain unchanged under `.local/models/hf/`.

GLM's newer tokenizer metadata is adapted for Transformers 4: `TokenizersBackend` becomes `PreTrainedTokenizerFast`, and the `extra_special_tokens` list uses the older `additional_special_tokens` key. The original `tokenizer.json` remains unchanged. Full vocabulary IDs and three sample encodings were checked for equality. These adaptations apply only to conversion inputs; the original snapshot stays unchanged.

F16 conversion is a runtime adaptation, not a claim of numerically identical MLX/CUDA logits. There is no Q4/Q8 quantization. Both original and converted assets are retained, using roughly twice the original checkpoint storage (about 21.5 GB including baseline model assets). Each CPU recognizer runs in its own process; it exits before the next loads. `gguf-inspection.json` records all eight converted artifacts and confirms only F16/F32 tensors, using metadata inspection without constructing a recognizer.

## Prompts, decoding and native confidence

Task strings match Sam: `Table Recognition:` for PaddleOCR-VL and GLM; the HTML table request for Monkey; newline + `Text Recognition:` / `Table Recognition:` for MinerU. Templates come from the exact publisher snapshots. The complete publisher image placeholder is replaced by mtmd's media marker, allowing mtmd to insert the correct image boundary tokens exactly once. Rendered templates are saved in `rendered-prompts.json`.

`native_vlm.cpp` chooses the argmax of unmodified logits. It uses no temperature adjustment, repetition penalty, grammar, top-k or top-p. EOS IDs come from each publisher generation config and EOS is excluded from confidence. The observer uses FP32 `log1p` normalization with compensated summation over competing logits, recording the selected logit, log probability, probability, other-token mass, token ID and raw emitted bytes. Token byte spans preserve split Unicode characters; invalid/truncated UTF-8 is flagged rather than inventing evidence. Sam's numeric/visible/structural/header/row-label summaries consume those emitted spans without reference-label access.

Tesseract retains native word certainty divided by 100; this is not a neural correctness probability. PP-OCRv5 uses Sam's native CTC character-score hook and unchanged crop helper. Its first processed crop compares instrumented and uninstrumented output when the user later runs it. No such inference equivalence check was performed at setup. Failed/missing recognition and unavailable native evidence remain explicit.

## Data selection and preservation

Source: `docling-project/FinTabNet_OTSL`, default config, test split; the downloaded revision and Parquet hashes are saved locally. Two test shards contain 10,397 rows across **50 issuers**. Sam's earlier/final selections cover 71 tables and 45 of those issuers. This cohort includes every one of those 71 original tables, then deterministically samples **1,929 additional rows** with seed `20261117`.

Additional eligibility follows Sam's geometry/numeric filters: 3–45 rows, 2–14 columns, at most 250 grid cells, image at least 200×80, at least six numeric strings. Mandatory original tables are retained even if ineligible under an extension filter. Selection uses only source data, never model outputs. To reach 2,000 tables in a 50-issuer split, the earlier two-tables-per-issuer cap is replaced by an explicit maximum of 100 tables per issuer.

All five issuers not used by Sam—ADS, AKAM, DLR, HOG, NFLX—are reserved for the **400-table test**. The other **1,600** tables are development. All Sam originals are development in this new experiment, including his previous final-test cases. Issuer groups never cross splits. **The final test has only five independent issuers despite its 400 tables.** More tables do not create more independent companies; use another corpus/split for broader issuer validation. Foundation-model pretraining overlap remains unknown.

Parquet stores PNG images while the viewer Sam downloaded emitted JPEG. JPEG quality 75 with 4:2:0 subsampling reproduces **all 71 exact original image SHA-256 values**. The same encoding is applied to every new table to avoid an encoding difference between cohorts. Original Parquet hashes and resulting input-image hashes are both retained. Annotation canonical hashing matches Sam's JSON convention, including escaped non-ASCII characters. `sam-included-71.json` records exact inclusion. `data/fintabnet_2000/seal.json` fixes config, input manifest and references before any inference.

References use original public cell text and restored HTML/OTSL structure; they are not human approvals. Sam's two flagged cases (`02146`, `09879`) stay included with explicit measurement flags; existing source/reference defects are not silently corrected or dropped. Four original legal-exhibit tables may have no eligible financial facts; they remain in execution coverage and have null financial targets. New public labels are also unaudited.

## Scoring and calibration when explicitly requested by the user

Structured configurations use Sam's `table_structure_v2.py` financial-association F1 and the pinned official GriTS content metric. Financial facts match section, row label, repeated-row occurrence, column-header path and value one-to-one. Wrong row/year associations, extras and omissions lose credit. Text-only configurations get the separate financial-number recall control, without invented structure scores. Failed required structure receives zero accuracy; missing outputs remain in the planned denominator.

When manually started, the default launcher processes all remaining 100-table batches across all seven configurations. It scores the cumulative completed prefix and saves results after each batch before automatically starting the next. `--one-batch` retains the option to exit after one batch. It uses the original manifest order within each split: 16 development batches, then 4 held-out test batches. The batch plan is fixed by the sealed manifest, configuration and batch size; it does not depend on model outcomes. Calibration begins only after all 1,600 development tables. The optional original `--full` launcher still starts with a one-table check through every recognizer before running the full experiment. All compatible inference outputs are reused. Calibration selects among Sam's twelve native summaries using whole-issuer inner holdouts and the 80% feature-coverage rule, then fits a monotone isotonic map to expected financial-association F1. Missing selected scores use the development mean and trigger review. The frozen file hashes data, scoring code, model conversions, rendered prompts, runtime build and adapter versions; test inference refuses to start without it. It cannot be refit after test inference starts. No recognizer weight training occurs.

Each completed batch replaces the root `summary.json` and `summary.md` with aggregates over all completed batches, preserving each milestone under `batch-results/` in both formats. Split summaries also receive Markdown versions. Markdown displays rounded metrics in readable tables; JSON retains full precision and detailed forecast metrics. Existing JSON can be rendered with `python markdown_report.py` without rerunning inference or scoring. The cumulative summary excludes tables beyond the completed prefix, includes failed/missing cases within the selected scoring denominator, and also keeps development/test summaries separate. Development accuracy remains descriptive; held-out forecast metrics use test rows only. Early manifest prefixes can have a different issuer/cohort mix from the full dataset. They should not be presented as the completed 2,000-table experiment. Native confidence features remain in the per-table pairs; calibration is not fitted provisionally on every batch.

Scoring caches each table/configuration row against the inference record's content hash, settings, scoring-code/data/reference provenance and (for test rows) frozen calibration hash. New or changed records are rescored, while unchanged rows are reused. The batch ledger advances only after inference, cumulative scoring, any required calibration freeze and cumulative JSON/Markdown writes succeed. The launcher lock remains held across batches and the cumulative timer spans the entire invocation. Failures stop continuous execution; interruptions retain raw records and score caches, and the next invocation resumes the same batch. An interruption after the final development freeze can finish checkpointing without rerunning frozen development inference.

Held-out evaluation reports forecast MAE/MSE, mean-only baseline and issuer-bootstrap intervals through Sam's functions. Existing measurement flags and the five-issuer limitation remain visible. An expected F1 is not the probability that an entire table is correct. This pipeline prepares an experiment; it does not establish useful predictive accuracy before execution and source/reference auditing.

## Manual commands and safe defaults

`pipeline.py`, `run.py`, `worker.py`, `evaluate.py` and `calibrate.py` require `--execute` to do experiment work. `pipeline.py` and `run.py` without it print plans. The manual command `python pipeline.py --execute` continuously runs remaining batches and saves cumulative results after each; add `--one-batch` to stop after one. `python pipeline.py --execute --full` uses the original uninterrupted full-run flow. Both consume local compute, not assistant tokens. To perform full stages separately:

```sh
python run.py --execute --split development
python evaluate.py --execute --split development
python calibrate.py --execute
python run.py --execute --split test
python evaluate.py --execute --split test
```

Use a new `--run-dir` for changed settings/models/data. Atomic per-table JSON and settings/image/source hashes protect resumption; `--retry-failed` explicitly retries failures. Before calibration freezes, the launcher resumes development; after freeze it skips development and retries/resumes only test. Development inference cannot run against a frozen directory. Reference hashes are explicitly included in the calibration freeze. An OS file lock prevents simultaneous model runs, and a separate launcher lock spans scoring/calibration too. Large files/data/runs are ignored by Git. No server, inference worker, calibration job or evaluation job is started by setup, activation or preflight.

`progress.py --watch` is a read-only terminal tracker. Each worker atomically saves a small per-configuration `progress.json`, with unique completed-output counts, successes, failures, current input, PID, timing and final state. On resume, workers rebuild counters from compatible per-table records once; pilot outputs and retries never add duplicate work units. The tracker reads these small summaries rather than repeatedly loading all native evidence. A dead PID or an interrupted worker is displayed as interrupted. The launcher checkpoints stages in `pipeline-status.json`; scoring checkpoints every ten tables. Inference percentage uses all 14,000 expected outputs as the denominator and counts failed attempts as processed, with success/failure counts shown separately. A model-specific mean time per completed output produces a rough remaining-inference estimate only after all remaining configurations have successful timing samples and no recorded failures. Scoring/calibration time is excluded from that estimate. No wall-time estimate is available before actual inference.

Setup verification includes compilation/linking, executable help/version, package versions/imports, immutable-asset/data hashes, exact inclusion of Sam's tables, split integrity and synthetic contracts. `test_progress.py` additionally exercises resumption, failed retries, interrupted processes, stage ordering, pilot-failure gating and freeze protection using temporary synthetic records and fake OCR/launcher subprocesses. Synthetic checks use fabricated strings/probabilities; they do not run a model, fit a calibrator or score the real dataset. Actual image inference and peak-memory/performance validation are deliberately left for the user's manual run.

Timing display: cumulative launcher time includes all stages; per-configuration time sums development/test worker sessions, including loading and processing. Monotonic clocks measure running sessions, persisted counters carry previous sessions across resume, and UTC checkpoints support live display without writing from the tracker. Pauses are excluded; dead processes stop accruing time at the last saved checkpoint. A hard kill can lose time after that checkpoint. Summaries predating cumulative timers use the greater of retained output durations and the last worker's saved timestamp span; overwritten earlier session overhead cannot be recovered exactly. A current table's elapsed time is subtracted from remaining-inference estimates to avoid counting its work twice. Per-configuration estimates are available independently, with separate MinerU text/table timing rows; the total inference runtime estimate excludes scoring/calibration. Changing this timing instrumentation does not change recognizer settings, model/source hashes, confidence records, scoring or calibration.
