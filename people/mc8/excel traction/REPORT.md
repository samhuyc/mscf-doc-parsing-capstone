# Excel extraction v1 results

## Result

The canonical extractor passed every check on the committed synthetic fixtures.

| Evaluation | Workbook | Passed | Accuracy |
| --- | --- | ---: | ---: |
| Level 1 reconstruction | `edge_cases.xlsx` | 33/33 | 100% |
| Level 1 reconstruction | `gold_financial_statement.xlsx` | 28/28 | 100% |
| Level 2 line-item survival | `gold_financial_statement.xlsx` | 5/5 records | 100% |
| Level 2 coordinate fidelity | `gold_financial_statement.xlsx` | 5/5 records | 100% |
| Level 2 value fidelity | `gold_financial_statement.xlsx` | 10/10 values | 100% |

The edge-case fixture verifies formula text, one present and one missing formula
cache, merged anchors and children, hidden rows and columns, a hidden sheet,
error cells, booleans, dates, number formats, multiple tables, titles, and
footnotes. The gold workbook contains separate balance-sheet and profit-and-loss
sheets with hand-labeled raw and formula-derived values.

## Interpretation

The Level 1 result shows that the JSON representation can reconstruct each
detected table without changing raw cell values or cached formula values. It is
primarily a serialization regression test.

The Level 2 result shows that the selected financial line items, values, and
coordinates survive the parser on the small gold fixture. It does not establish
performance on sponsor workbooks, unusual Excel layouts, or financial semantic
normalization. Those claims require a representative real test set.

Machine-readable synthetic-fixture results are in `results/evaluation.json`.
The fixtures are deterministically generated by `scripts/generate_fixtures.py`
and contain no restricted data.

## Converted benchmark cases

The parser was also evaluated on 11 sponsor-pilot reference tables and all 278
official TAT-QA development tables after deterministic conversion to `.xlsx`.

| Metric | Sponsor pilot | TAT-QA dev |
| --- | ---: | ---: |
| Nonblank values preserved | 217/217 (100%) | 8,773/8,773 (100%) |
| Cell coordinates present | 237/237 (100%) | 10,411/10,411 (100%) |
| Merged-cell metadata | 14/14 (100%) | Not applicable |
| Exactly one table detected | 11/11 (100%) | 254/278 (91.4%) |
| Exact table boundary | 11/11 (100%) | 120/278 (43.2%) |
| Correct title association | 11/11 (100%) | 120/278 (43.2%) |
| Correct header rows | 9/11 (81.8%) | 120/278 (43.2%) |

The reader preserved every nonblank value and coordinate. The weak point is the
v1 table detector: sparse first headers and one-cell section rows are often
excluded or split into separate tables. Two sponsor tables also have multi-row
headers, while v1 labels only the first row as a header.

Thirteen sponsor empty strings and 1,638 TAT-QA empty strings became `null`.
`openpyxl` normalizes an explicit empty string to a blank cell when the
controlled workbook is saved and loaded. This does not alter nonblank content,
but the strict empty-string distinction is not preserved.

Machine-readable details, including every failed table-layout case, are in
`results/benchmark_cases.json`. The committed workbooks and gold matrices are
in `benchmark_cases/`. These are converted benchmark tables—not native source
Excel workbooks—and the sponsor-pilot references remain preliminary rather
than independently human verified.
