# Source-level examples to show in the meeting

These are observations from the six selected source pages, not whole-document accuracy judgments. Open [the comparison](evaluation/REVIEW.html) to inspect the original page and predictions together.

- **EDF, physical page 3:** the OCR pipeline retains all 15 selected numbers, including `(84.6)` and `(92.0)`, but concatenates multiple financial row labels into a single spanning cell. Its three selected rows fail the exact-cell check. PyMuPDF4LLM also bundles multiple printed rows into multiline table cells. The VLM preserves all three checked rows and all 15 values correctly. Full-document wall time is 30.8s for OCR versus 124.8s for VLM. This illustrates why page-level numeric recall is insufficient.
- **Peterborough, physical page 2:** the OCR pipeline emits parts of the balance sheet as one-cell rows containing both labels and values. The prior-year tangible-assets value `992,467` is missing. The VLM recovers that value and all three checked rows with the correct ordered cells: six of six selected values. Full-document time is 48.1s for OCR versus 241.4s for VLM. No values were repaired. Native PyMuPDF4LLM has no text layer to read and returns page images without transcription.
- **CVS, physical page 6:** PyMuPDF4LLM preserves all six selected financial values and their nearby labels as plain text, but does not export them as an HTML table. The strict row-cell score is zero despite readable text. This is a representation limitation, not a claim that every value was lost.
- **Rolls-Royce release, physical page 13:** native PyMuPDF4LLM retains headings, EPS text and footnotes, but exports the main income-statement area as image crops. The six selected income-statement values are absent from its searchable text. OCR and VLM both preserve all six values in the three correct rows. Image preservation is useful for later visual review, but does not itself satisfy structured financial extraction.
- **CVS, physical page 8:** PyMuPDF4LLM returns image assets with no transcribed text, accounting for its additional empty-text page beyond the 51 image-only Companies House pages.
- **Hippodrome, physical page 20:** OCR and VLM both preserve all six selected values and all three selected income-statement rows. The full document takes 179.9s with OCR and 983.7s with VLM. On these particular checks, the additional VLM runtime produces no improvement; this does not establish equal accuracy on the remaining pages.
- **Rolls-Royce presentation, physical page 9:** OCR and VLM both preserve all 11 selected values in the correct three table rows. The native PyMuPDF4LLM export has none of these values in searchable text. Full-document times are 58.3s for OCR, 335.6s for VLM and 2.8s for PyMuPDF4LLM.
