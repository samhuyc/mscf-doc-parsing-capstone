# Source-level examples to show in the meeting

These observations describe the current OCR-enabled PyMuPDF results and the existing MinerU runs. They concern six selected source pages, not whole-document accuracy. Open [the comparison](evaluation/REVIEW.html) to inspect the source pages and predictions together. The scoring rules and reference values are unchanged.

- **EDF, physical page 3:** MinerU OCR retains all 15 selected numbers but concatenates several financial row labels, failing the three exact-cell checks. Both MinerU VLM and the updated PyMuPDF pipeline retain all 15 values in the correct three checked rows. PyMuPDF's layout/table upgrade resolves the earlier multiline-cell issue on these checks.
- **Peterborough, physical page 2:** local Tesseract recovers all six selected values, including `992,467`, which MinerU OCR misses. PyMuPDF places the values in an HTML table but inserts blank columns between them. All three rows therefore fail the unchanged strict ordered-cell check. This is a structural mismatch, not missing numeric text; a future metric should distinguish harmless spacer columns from incorrect year associations. MinerU VLM passes all three rows.
- **CVS, physical page 6:** the updated PyMuPDF pipeline now exports the six selected values in three correct HTML table rows; the old native-only configuration returned them as plain text. All three current pipelines pass these selected rows.
- **Rolls-Royce release, physical page 13:** the updated PyMuPDF pipeline extracts the main income statement as an HTML table and passes all six selected values / three rows. Its OCR callback was never needed anywhere in this digital document, so this gain comes from the upgraded layout/table handling, not OCR. The earlier native-only export saved the table area as images.
- **Hippodrome, physical page 20:** all three pipelines preserve the six selected values and three income-statement rows. PyMuPDF now applies local OCR across all 39 scanned pages and produces text on every page; its full-document time is 76.0 seconds.
- **Rolls-Royce presentation, physical page 9:** the updated PyMuPDF pipeline now retains all 11 selected values in the correct three rows, matching MinerU on these checks. The previous native-only output omitted these values from searchable text.

Across all six documents, PyMuPDF now has text on 140/140 pages (including all 51 scan pages), retains 50/50 selected values and passes 15/18 strict row checks in 142.5 seconds. The previous native-only results remain in Git history at `9cbf66a`; this update changed package version, layout and table extraction as well as adding OCR. No parser predictions were manually repaired.
