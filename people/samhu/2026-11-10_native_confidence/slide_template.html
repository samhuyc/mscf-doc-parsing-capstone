Before text recognition

How pixels become text predictions

PaddleOCR

  1. Detect text regions on the page.
  2. Crop and straighten each region.
  3. Encode its pixels into visual features.
  4. Predict characters and blanks across positions; CTC collapses the sequence.

MinerU recognition

  1. Represent an image as small patches.
  2. Encode patches into visual features.
  3. Use those features and prior output to predict the next text token.

The full parser first identifies layout regions. Our prototype feeds whole pages to the recognition model directly.

Image patches are not predefined words or characters. Region cropping does not determine how confidence must be aggregated. Paddle model · MinerU architecture

Document aggregation

Two summaries of the emitted text

Character-weighted mean

C = Σ wᵢpᵢ / Σ wᵢ

Longer output units contribute more.

For PaddleOCR, this pools the decoded character scores directly, including spaces.

Geometric mean

G = exp(mean(log pᵢ))

Low-probability decisions have a stronger effect.

Each emitted unit has equal weight. A zero probability makes the summary zero.

We test these summaries against correctness; neither is automatically P(document correct).

Both summaries describe produced text. Omitted text has no emitted probability, and repetitive output can dominate an average.
